## 1. 한눈에 〔사람〕
- **한 줄 소개:** e스포츠 행사 부스에 줄 선 팬이 / 무전처럼 뜨는 팀 콜("North Stairs, two!")을 읽고 듣자마자 탑뷰 미니맵에서 그 자리를 마우스로 찍어서 / "나 콜 반응 0.6초야" 라는 숫자와 옆 모니터 순위표에 이름이 오르는 짜릿함을 느끼는 60초 게임.
- **장르 / 플랫폼 / 조작:** 반응 훈련 미니게임 / PC 브라우저(Chrome·Edge, 1920×1080 전체 화면이 1순위, 창 크기에 맞춰 줄어듦) / **마우스 왼쪽 누르기 하나**. 터치 화면도 같은 코드로 된다(pointer 이벤트). 키보드는 운영자 전용.
- **주 레퍼런스 (하나):** 특정 게임 없음. **"반응 훈련 미니게임의 일반 구조"** 세 가지만 따른다 — ① 짧은 한 판(시간 제한) ② 끝나면 반응속도·정확도를 숫자로 보여 줌 ③ 순위표. 이름·그림·소리·화면 배치는 어떤 게임에서도 가져오지 않는다.
- **보조 레퍼런스 (0~2개):** 없음.
- **레퍼런스와 일부러 다르게 할 점:** 과녁을 **보고** 쏘는 조준 훈련이 아니라, **말(콜)을 자리로 바꾸는** 훈련이다. 과녁은 화면에 미리 안 뜬다 — 콜 문장을 이해해야 어디를 찍을지 안다. 그래서 재는 것도 "손 빠르기"가 아니라 "콜 이해 → 위치 찾기 → 클릭" 전체 시간. 중반부터 구역 이름표가 사라지고(맵 암기), 후반엔 두 곳을 순서대로 찍는 콜이 나온다.
- **타깃 플레이어:** 부스 줄에서 1~2분 짬이 난 팬. 설명을 안 읽는다. 뒤에 다음 사람이 서 있다. 그리고 부스를 지키는 운영자 1명(하루 종일 켜 두고 손 안 대고 싶다).
- **한 판 길이 / 전체 플레이 시간:** 플레이 60초. 시작 클릭부터 다음 사람이 시작할 수 있을 때까지 최대 95초(카운트다운 3 + 60 + 결과·이니셜 ≤ 20 + 순위 표시 ≤ 8 + 여유). 요강 권장 "3분 미만" 안.

## 2. 핵심 재미 (필러) 〔사람〕
> 모든 결정이 이 3개 중 하나를 강화해야 한다. 아니면 안 만든다.
1. **콜 → 클릭의 짜릿함** — 콜이 뜨는 순간 무전음, 맞히면 0.1초 안에 초록 번쩍 + 점수 + 반응 시간(초). 연속으로 맞히면 소리가 점점 높아진다.
2. **내 숫자, 내 등급** — 끝나면 평균 반응 시간(ms)·정확도(%)·최고 연속·등급 이름(Rookie~IGL). 친구에게 말할 수 있는 숫자 하나.
3. **부스가 편하다** — 설명 없이 시작, 한 사람 95초 안, 끝나면 알아서 처음으로, 옆 모니터엔 오늘 순위, 와이파이 없어도 하루 종일.

## 3. 핵심 루프
### 3.1 30초 루프 (손으로 하는 것)
무전음 + 콜 문장이 뜸 → 맵에서 그 구역을 찾음 → 누름 → 맞으면 초록·점수, 틀리면 주황·정답 구역 표시 → 0.3초 뒤 다음 콜.
### 3.2 5분 루프 (한 구역)
대기 화면에서 아무 데나 클릭 → 3·2·1(이때 맵과 이름표를 미리 봄) → 60초 플레이(3단계로 어려워짐, §4.3) → 결과(점수·반응·정확도·연속·등급) → 이니셜 3글자 → 순위표에서 내 줄 강조 → 대기 화면.
### 3.3 1시간 루프 (성장)
성장 시스템 없음. 대신 **오늘 순위표**: 줄을 다시 서서 내 점수·친구 점수·오늘 1등을 깬다. 보조 모니터가 그걸 계속 보여 준다.
### 3.4 한 판 / 세션 끝
- 60초가 되면 진행 중이던 콜은 버리고(점수·실패 둘 다 아님) 끝 경적 → 결과 화면.
- 결과 화면에서 20초 동안 입력이 없으면 이름 `---` 로 저장하고 넘어간다. 순위 표시는 8초 뒤(또는 클릭) 대기 화면으로.
- 어느 화면이든 다음 판은 **완전히 새 상태**에서 시작한다(§4.7 초기화 규칙).

## 4. 시스템
> 시스템마다 같은 틀: **무엇 / 규칙 / 숫자 / 예외 / UI**

### 4.1 조작·입력 (캐릭터·조작)
- **무엇:** 마우스 왼쪽 누르기 하나로 전부 한다.
- **규칙:** `pointerdown` 순간에 판정한다(뗄 때 아님 — 반응 시간이 정확해야 한다). 좌표는 화면 → 무대(1920×1080 논리 좌표) → 맵(1000×1000 단위)으로 바꾸는 **순수 함수** 하나를 쓴다. 반응 시간 = 콜이 화면에 그려진 프레임의 시각 → `pointerdown` 의 `event.timeStamp`.
- **숫자:** §6.1.
- **예외:** 오른쪽 버튼·휠·드래그·글자 선택·우클릭 메뉴는 전부 막는다. 플레이 중 맵 밖(오른쪽 패널) 클릭은 무시. 맵 안인데 어느 구역도 아닌 곳은 **오답**(막 찍기 방지). 두 손가락 터치는 첫 번째만.
- **UI:** 커서는 십자 모양(CSS `crosshair`). 구역 위에 올려도 강조하지 않는다(힌트가 되면 안 됨).

### 4.2 콜 판정 (전투)
- **무엇:** 지금 떠 있는 콜과 클릭한 구역을 비교한다.
- **규칙:**
  - 정답: 콜의 구역 안을 제한 시간 안에 누름 → 점수(§4.4), 연속 +1.
  - 오답: 다른 구역 또는 빈 곳을 누름 → 0점, 연속 0, 그 콜은 끝. 정답 구역이 0.6초 동안 테두리+이름표로 보인다(배우게).
  - 시간 초과: 오답과 같다. 글자만 `TOO SLOW`.
  - 두 곳 콜(§4.3): 첫 구역 → 둘째 구역 순서로 눌러야 한다. 각각 따로 점수. 첫 클릭이 틀리거나 순서가 바뀌면 콜 전체가 오답(목표 2개 실패로 센다).
  - 판정이 끝나면 `CALL_GAP_MS` 뒤 다음 콜.
- **숫자:** §6.1 · §6.3.
- **예외:** 판정 직후 `CALL_GAP_MS` 동안의 클릭은 무시(연타가 다음 콜 오답이 되지 않게). 60초가 끝난 뒤의 클릭은 무시.
- **UI:** 정답 = 구역 초록 번쩍(150ms) + 구역 위로 `+142` 와 `0.61s` 가 떠오름. 오답 = 누른 자리에 주황 X + 화면 살짝 흔들림(120ms, 6px) + 정답 구역 테두리.
- **구현:** `core/game.ts` 의 리듀서 `step(state, event)` 하나. 이벤트는 `TICK(now)` · `CLICK(mapX, mapY, now)` 둘뿐. 시계와 난수는 밖에서 넣는다(테스트·배속·봇이 같은 코드를 쓴다).

### 4.3 콜 생성·난이도 단계 (스킬)
- **무엇:** 60초가 3단계로 어려워진다. 이것이 "새로움"의 핵심이다.
- **규칙:**
  | 단계 | 이름(화면 표시) | 구간 | 이름표 | 콜 종류 |
  |---|---|---|---|---|
  | 1 | `WARM-UP` | 0~15초 | 보임 | 한 곳 |
  | 2 | `LIVE` | 15~40초 | **2초에 걸쳐 사라짐** (구역 그림은 남음) | 한 곳 |
  | 3 | `CLUTCH` | 40~60초 | 안 보임 | 한 곳 50% / 두 곳 50% |
  - 한 곳 콜: 구역 + 인원(1~3). 문장 `North Stairs, two!`. 인원이 많을수록 기본 점수가 크다(§6.2) — 플레이어가 몰라도 되는 숨은 깊이. 맞히면 그 수만큼 점이 구역에 찍힌다.
  - 두 곳 콜: 문장 `Tunnel, then Crane!`. 인원 없음.
  - 구역 고르기: 시드 난수(mulberry32)로 고르되 **최근 2번 나온 구역은 제외**. 두 곳 콜의 두 구역은 서로 다르다.
  - 시드: 판마다 `Date.now()`. 주소에 `?seed=` 가 있으면 그 값(테스트·영상용).
- **숫자:** §6.3.
- **예외:** 단계가 바뀌는 순간 떠 있던 콜은 원래 조건 그대로 끝까지 간다.
- **UI:** 단계가 바뀌면 타이머 옆 글자가 바뀌고 0.8초 동안 크게 번쩍(`LIVE — LABELS OFF`, `CLUTCH — DOUBLE CALLS`).

### 4.4 점수·연속·등급 (성장)
- **무엇:** 빠를수록, 연속으로 맞힐수록 점수가 크다.
- **규칙 (순수 함수 `core/scoring.ts`):**
  - `speed = clamp((T − rt) / (T − RT_FLOOR_MS), 0, 1)` — `T` 는 그 콜의 제한 시간, `rt` 는 반응 시간(ms).
  - `points = round(base × (0.5 + 0.5 × speed) × mult)`
  - `mult = min(1 + 0.1 × 연속(이번 것 맞히기 전), MULT_CAP)`
  - `base`: 인원 1·2·3 → 100·150·200, 두 곳 콜의 각 구역 → 150.
  - 정확도 = 맞힌 목표 ÷ 끝난 목표(두 곳 콜은 목표 2개). 평균 반응 = 맞힌 클릭의 `rt` 평균(두 곳 콜의 둘째는 첫 클릭부터 잰다).
  - 등급: 점수 구간(§5.6).
- **숫자:** §6.2.
- **예외:** 끝난 목표가 0이면 정확도 0%, 평균 반응은 `—`.
- **UI:** 오른쪽 패널에 점수(큰 숫자), 연속 `x1.4` (연속 3 이상이면 색이 금색으로).

### 4.5 결과·이니셜 (아이템·인벤토리·장비)
- **무엇:** 한 판의 성적표 + 이름 3글자.
- **규칙:** 결과 화면에 점수(카운트업 0.8초), 등급, 평균 반응(ms), 정확도(%), 최고 연속, 오늘 몇 등인지(`#4 TODAY`). 그 아래 이니셜 3칸 + A~Z 글자판(마우스로 누름) + `⌫` + `OK`. 3글자가 차면 `OK` 가 켜진다.
- **숫자:** §6.4.
- **예외:** 20초 무입력 → `---` 로 저장. 금지 3글자(§5.9 목록)는 `OK` 를 누르면 `***` 로 저장. 키보드로 쳐도 된다(부스에 키보드가 있으면).
- **UI:** §8.1 S4.

### 4.6 리더보드·보조 모니터 (경제)
- **무엇:** 와이파이 없이 도는 오늘 순위표. 게임 창과 **다른 창(보조 모니터)** 에 띄운다.
- **규칙:**
  - 점수는 이 브라우저의 `localStorage` 에만 저장한다(§4.8). 서버·네트워크 요청 0.
  - 보조 화면은 같은 사이트의 `board.html`. 운영자 메뉴(§4.7)의 `Open leaderboard window` 로 새 창을 열어 보조 모니터로 끌어다 놓고 전체 화면.
  - 갱신: 저장 직후 `BroadcastChannel('calloutrush')` 로 `{type:'scores-updated'}` 를 보낸다. 보조 화면은 이것 + `storage` 이벤트 + 5초마다 다시 읽기(안전망) 중 먼저 오는 것으로 다시 그린다.
  - 보조 화면 내용: `TODAY'S TOP 10`(순위·이름·점수·평균 반응), `ALL-TIME TOP 5`, 맨 아래 `BEAT #1: 7,420`. 새 기록이 들어오면 그 줄이 3초 동안 금색으로 번쩍이고 제자리로 미끄러져 들어간다.
  - "오늘" = 이 컴퓨터의 현지 날짜. 자정이 지나면 오늘 목록이 저절로 비고(자료는 남음) 전체 기록은 그대로.
  - 게임 창에서도 이니셜 뒤 8초 동안 오늘 TOP 10 을 보여 준다(내 줄 강조, 10등 밖이면 맨 아래에 `#23 YOU`).
- **숫자:** §6.4.
- **예외:** 동점은 먼저 낸 사람이 위. 오늘 기록이 없으면 `BE THE FIRST ON THE BOARD`. 보조 창이 없어도 게임은 똑같이 돈다.
- **UI:** §8.1 S5 · S6.

### 4.7 부스 운영 — 대기 화면·자동 초기화·운영자 메뉴·내구 (퀘스트·대화)
- **대기 화면(attract):** 제목 + `CLICK TO PLAY`(깜빡임) + 한 줄 설명 `Read the call. Click the spot.` + 오늘 TOP 3. 20초 동안 아무도 안 건드리면 뒤에서 **봇이 실제 게임을 시연**한다(반투명 `DEMO` 표시, 소리 없음, 점수 저장 안 함). 아무 데나 누르면 즉시 새 판.
- **자동 초기화 (다음 사람이 깨끗한 판을 받는다):** 판을 시작할 때 게임 상태를 새로 만든다(이전 판 객체를 고쳐 쓰지 않는다). 타이머·애니메이션·소리 노드·이벤트 리스너는 판이 끝날 때 전부 정리한다. 검사: 판 사이에 살아 있는 타이머 수·DOM 노드 수·리스너 수가 같아야 한다.
- **무입력 처리:** 플레이 중 12초 동안 클릭이 없으면(사람이 떠남) 판을 버리고 대기 화면으로(점수 저장 안 함). 결과 20초, 순위 8초(§3.4). 탭이 숨겨지면 판을 버린다.
- **운영자 메뉴:** `Ctrl+Shift+O`(플레이어는 모르는 키). 항목: `Open leaderboard window` · `Fullscreen` · `Mute` · `Export scores (CSV)` · `Clear today's scores`(한 번 더 확인) · `Booth health`(켠 뒤 판 수, JS 힙 MB, 최근 1분 평균 프레임 ms, 오류 횟수). 닫기는 `Esc` 또는 `Close`.
- **안 죽는다:** `window.onerror`·`unhandledrejection` 이 나면 오류 횟수를 올리고 3초 뒤 대기 화면으로 새로 고침. 화면 꺼짐 방지는 `navigator.wakeLock`(되면).
- **오프라인:** 서비스 워커가 정적 파일 전부를 미리 저장한다 — 주소를 와이파이 있을 때 **한 번** 열면 그 뒤로는 와이파이 없이 열린다. zip 은 `dist` + 의존성 없는 작은 정적 서버(`serve.mjs`) + `start.command`/`start.bat`. (`file://` 더블클릭은 모듈 스크립트가 막혀 안 됨 — README 에 적는다.)
- **내구 증명:** `npm run soak` — Playwright 로 봇이 1000판을 연속으로 한다(시계 배속 `?timescale=30`, 결과·이니셜·순위·대기 화면까지 매 판 전부 지나감). 50판마다 강제 GC 뒤 JS 힙·DOM 노드 수·프레임 시간 p95·저장 크기를 재서 `docs/soak-report.md`(영어, 표+그래프용 CSV)로 낸다. 추가로 **실제 속도 60분**(약 40판) 한 번. 합격선은 §6.4.
- **UI:** §8.1 S1 · S7.

### 4.8 저장·불러오기
- **무엇:** 점수 목록과 설정만 저장한다. 게임 진행은 저장하지 않는다.
- **규칙:** `localStorage` 키 `calloutrush.v1.scores` = `[{id, name, score, acc, avgRt, streak, ts}]`, `calloutrush.v1.settings` = `{muted}`, `calloutrush.v1.health` = `{errors}`. "오늘" 은 `ts` 로 계산한다(따로 저장 안 함).
- **숫자:** 최대 500건(§6.4). 넘으면 "오늘 것 전부 + 전체 상위" 를 남기고 낮은 옛 기록부터 지운다.
- **예외 (절대 안 죽는다):** JSON 이 깨졌으면 원본을 `calloutrush.v1.scores.bad` 로 옮기고 빈 목록으로 시작. 저장 공간이 꽉 차면 줄이고 한 번 더, 그래도 안 되면 메모리에만 두고 운영자 메뉴에 경고. `localStorage` 자체가 막혀 있으면 메모리로만 돈다.
- **개인정보:** 이니셜 3글자와 점수만. 그 밖의 어떤 것도 모으지 않고 어디로도 보내지 않는다.

| 한 사람 최대 시간 | 95 | 초 | 3+60+20+8+여유 4. 요강 "3분 미만" 의 절반 |
| 점수 저장 최대 | 500 | 건 | 건당 약 90바이트 → 45KB, 저장 한도(약 5MB)의 1% |
| 순위표 갱신 지연 | ≤ 1000 | ms | BroadcastChannel 은 즉시. 안전망 다시 읽기는 5초 |
| 내구: 판 수 / 배속 | 1000 / 30 | 판 / 배 | 하루 8시간 × 시간당 40명 = 320명 → 3일치 |
| 내구 합격: JS 힙 증가 | ≤ 10% 또는 ≤ 5MB | 50번째 판 대비 1000번째 판(강제 GC 뒤) | 새는 게 있으면 1000판이면 드러남 |
| 내구 합격: DOM 노드 수 | 판 사이 같음(±0) | 개 | 화면을 다시 쓰는지 확인 |
| 내구 합격: 프레임 p95 | ≤ 20 | ms | 60fps(16.7ms)에 여유 20% |
| 내구 합격: 오류 | 0 | 회 | 콘솔 오류·잡힌 예외 전부 |
| 빌드 크기(`dist`, gzip 전) | ≤ 500 | KB | 그림·소리 파일이 없으니 가능. 오프라인 저장이 1초 안 |

## 9. 기술 결정
- **스택:** TypeScript + Vite. **렌더는 Canvas 2D 직접**(Phaser 안 씀 — 직사각형 12개와 글자뿐이라 엔진이 필요 없고, 의존성이 적을수록 1000판 내구와 빌드 크기에 유리). 글자 많은 화면(S1·S4·S5·S6·S7)은 DOM+CSS, 맵과 연출만 Canvas. UI 프레임워크 없음.
- **폴더:** `app/` — `src/core/`(순수 함수: config·zones·calls·scoring·game·initials·scores·bot, 전부 `*.test.ts`) · `src/ui/`(화면) · `src/audio/` · `src/main.ts` · `src/board.ts` · `index.html` · `board.html` · `public/`(sw.js·글꼴) · `scripts/`(inspect·shot·soak·zip).
- **도구:** Node 24(`/opt/homebrew/opt/node@24/bin`), Vitest(단위), ESLint+typescript-eslint, Playwright(캡처·통 플레이·내구). 실행 의존성은 0개가 목표(전부 devDependencies).
- **CHECK:** `cd app && npm run check` = `tsc --noEmit` → `eslint` → `vitest run` → `vite build` → `npm run inspect`(WebStorm 헤드리스 검사, §9.1).
- **테스트용 주소 인자:** `?seed=<n>`(같은 콜 순서) · `?timescale=<n>`(시계 배속) · `?bot=rookie|regular|pro`(봇이 플레이) · `?state=attract|play|result|board&at=<ms>`(그 화면·그 시각에서 멈춤 — 캡처용). 인자가 없으면 아무 영향 없음.
- **캡처:** `npm run shot -- <state> <파일>` 이 `vite preview` 를 띄우고 Playwright 로 1920×1080 PNG 를 `captures/` 에 낸다.
- **배포:** GitHub Actions 가 `app/dist` 를 GitHub Pages 로 올린다(Vite `base: './'`). zip 은 `npm run zip` → `제출본/callout-rush-web.zip`, GitHub 릴리스에 첨부.
- **저장:** `localStorage`(§4.8). 서버 없음. 네트워크 요청은 첫 로드의 정적 파일뿐.
- **라이선스:** 루트 `LICENSE` = MIT 표준 문구(GitHub 가 자동 인식 → About 에 표시). 글꼴은 OFL 문서를 같이 넣는다.
- 자세한 이유는 `docs/decisions/`.

### 9.1 JetBrains 도구 사용과 증빙 (1단계 탈락 방지 — 최우선)
규정: JetBrains IDE · JetBrains Air(단독 앱·IDE 플러그인·웹·CLI) · Junie 중 **하나 이상**. 다른 편집기·에이전트와 같이 써도 된다. 저장소에 `.idea`·`.junie`·`.air` 커밋 권장, 설명문에 "어느 도구가 무엇을 했는지" 필수.
**원칙: 거짓으로 쓰지 않는다.** 실제로 돌린 것만, 숫자와 커밋 해시로 적는다. 주 개발은 Claude Code 자율 루프이고 JetBrains 도구는 아래 역할을 **실제로** 맡는다.
